# 参考图局部意图设计规格

## 背景

当前参考图组已经能把画布图片加入 ReferenceSet，并为每张图创建 ReferenceIntent。这个模型适合“整张图作为主体 / 风格 / 构图 / 局部元素参考”的简单场景，但对创作者来说还不够细。

真实创作里，一张参考图经常同时包含多个可复用信息：

- 画面里的某个主体或物体。
- 某一块材质、纹理、色彩或光照。
- 整体构图和镜头位置。
- 某个局部 UI、装饰元素、道具或姿态。

因此产品模型应该从“参考意图等于一张图”升级为“参考意图等于一张图里的某个用途”。同一张源图可以派生多个意图，每个意图都有独立角色、权重、备注和可选裁剪区域。

## 目标

- 支持一张源图创建多个 ReferenceIntent。
- 支持对源图手动框选局部区域，并把区域作为意图的一部分保存。
- 参考意图列表能清楚展示每个意图指向的是整图还是局部区域。
- 编译预览和后续生成请求能输出结构化 crop 信息，方便模型网关或后续 adapter 使用。
- 保持第一版交互轻，不引入复杂抠图、自动识别或多层标注系统。

## 非目标

- 第一版不做自动元素识别。
- 第一版不做精确多边形、蒙版、钢笔路径或背景移除。
- 第一版不做图片内部对象命名系统。
- 第一版不做跨源图批量标注。
- 第一版不改变 MediaObject 的物理文件存储方式。
- 第一版不要求模型一定理解 crop，只保证产品数据和提示词编译表达清楚。

## 推荐方案

采用 **单源图，多意图，矩形区域** 的方案。

一张画布来源图仍只在“画布来源”区域出现一次。用户点击来源图后，不再只有“加入”这个单一动作，而是进入一个轻量菜单：

- `整图参考`
- `框选局部`
- `提取风格`

`整图参考` 会沿用当前行为，创建没有 crop 的 ReferenceIntent。

`框选局部` 会打开源图预览浮层，用户拖拽矩形框，选择角色、权重和备注后保存。保存后创建 ReferenceIntent，并把矩形区域写入 `cropJson`。

`提取风格` 第一版不做 AI 分析，只是创建 `role=style` 的整图意图，并鼓励用户在备注中写“色彩 / 材质 / 光影 / 笔触”等约束。后续可以接 AI 自动总结风格词。

## 数据模型

现有 `ReferenceIntent` 已经有 `cropJson`、`analysisJson` 和 `metadataJson`，第一版直接使用这些字段，不新增表。

### cropJson

使用相对坐标，避免图片尺寸变化后失效。

```json
{
  "type": "rect",
  "x": 0.12,
  "y": 0.18,
  "width": 0.32,
  "height": 0.41
}
```

规则：

- `x`、`y`、`width`、`height` 都是 0 到 1 的数字。
- 坐标相对于原图自然宽高。
- 没有裁剪时 `cropJson` 为空对象。
- 保存前前端限制最小区域，避免误点生成极小 crop。

### metadataJson

继续记录画布来源关系：

```json
{
  "canvasNodeId": "image-xxx",
  "canvasNodeTitle": "画布图片",
  "regionLabel": "右侧彩色球",
  "sourceMode": "region"
}
```

规则：

- `canvasNodeId` 用于来源卡片识别“已加入”。
- `regionLabel` 可选，用于未来在 UI 中显示更友好的名称。
- `sourceMode` 为 `whole | region | style`。

## 前端交互

### 来源卡片

来源卡片保留缩略图和标题，但按钮改成更清晰的动作：

- 未加入任何意图：显示 `添加`
- 已有整图意图：显示 `已添加`
- 已有多个意图：显示 `2 个意图`

点击卡片或动作按钮打开来源菜单，而不是直接创建唯一意图。

菜单项：

- `整图参考`：立即创建整图意图。
- `框选局部`：打开区域选择浮层。
- `提取风格`：立即创建风格意图。

### 区域选择浮层

区域选择浮层在参考图组编辑器内部打开，避免离开画布。

内容：

- 大图预览，保持图片比例。
- 可拖拽矩形框。
- 角色选择：主体一致、风格参考、构图参考、局部元素。
- 权重输入。
- 备注输入。
- 保存 / 取消。

第一版只需要一个矩形框。用户如果想从同一张图里取多个元素，就重复进入“框选局部”，每次保存一个独立意图。

### 参考意图行

意图行展示：

- 缩略图：如果有 crop，则显示裁剪后的局部预览；否则显示整图。
- 角色：分段控件。
- 权重。
- 备注。
- 启用开关。
- 排序按钮。
- 删除按钮。

删除按钮应加入第一版，因为多意图会自然产生试错，用户需要快速清理旧意图。

## 后端行为

后端现有 `CreateReferenceIntent` / `UpdateReferenceIntent` 已支持 `cropJson` 和 `metadataJson`，第一版只需要加强校验：

- `cropJson.type` 为空或 `rect`。
- `rect` 坐标必须是合法数字。
- `width`、`height` 必须大于最小阈值。
- 更新 intent 时保留调用方传入的 `metadataJson`。

不在后端生成裁剪文件。原因是第一版重点是表达创作意图，而不是派生媒体文件。后续如果某些模型 API 必须上传裁剪后的图片，可以在模型 adapter 层临时裁剪，或者新增 `DerivedMediaObject`。

## 编译预览

编译预览需要同时输出文本和结构化 JSON。

文本示例：

```text
参考图要求:
1. 局部元素参考: media:xxx crop x=0.12 y=0.18 w=0.32 h=0.41 Weight 1.00. 参考右侧彩色球的透明质感
2. 风格参考: media:xxx Weight 0.80. 保持糖果色、柔和高光和玩具感
```

结构化 JSON 示例：

```json
{
  "referenceSetId": "set-xxx",
  "references": [
    {
      "id": "intent-xxx",
      "role": "element",
      "weight": 1,
      "mediaObjectId": "media-xxx",
      "crop": {
        "type": "rect",
        "x": 0.12,
        "y": 0.18,
        "width": 0.32,
        "height": 0.41
      },
      "note": "参考右侧彩色球的透明质感"
    }
  ]
}
```

## 错误处理

- 图片没有内容或媒体读取失败：提示“无法读取这张参考图”。
- 保存区域太小：提示“框选区域太小，请重新选择”。
- 后端校验失败：保持浮层打开，并显示保存失败提示。
- 用户未登录：保持当前云端参考图组的登录限制，不允许创建 ReferenceIntent。
- 删除失败：保留原意图，显示失败提示。

## 测试策略

前端测试：

- crop 坐标归一化工具测试。
- 来源图多意图计数测试。
- ReferenceIntent metadata 保留测试。
- 编译预览响应兼容空数组测试继续保留。

后端测试：

- 创建合法 crop 的 ReferenceIntent。
- 拒绝非法 crop 坐标。
- CompileReferenceSetPreview 输出 crop 到 JSON 和文本。

手测路径：

- 同一张图创建整图参考。
- 同一张图创建两个局部参考。
- 修改角色、权重、备注后刷新仍保留。
- 删除一个局部参考，不影响同图其他意图。
- 预览编译结果能看出每个参考对应整图还是局部。

## 分阶段实施

### 第一阶段

- 引入来源卡片菜单。
- 新增区域选择浮层。
- 保存 `cropJson` 和 `metadataJson.sourceMode`。
- 意图行显示局部预览。
- 新增删除 ReferenceIntent。
- 编译预览输出 crop。

### 第二阶段

- 在画布图像工具栏中增加“加入参考局部”快捷入口。
- 支持给局部区域命名。
- 支持复制某个局部意图到另一个 ReferenceSet。

### 第三阶段

- 接 AI 自动分析源图，建议可拆元素、风格词和构图描述。
- 根据模型能力决定是否在 adapter 层裁剪图片并上传。
- 对支持多参考图控制的模型生成更细的 adapter 参数。

## 自检

- 没有引入新的存储表，第一版范围足够小。
- 没有依赖模型调用，用户可以在本地无额度状态下测试。
- 数据结构保留了未来自动识别和 adapter 裁剪的扩展空间。
- 交互上支持用户真实需求：一张复杂图拆成多个可控参考意图。
