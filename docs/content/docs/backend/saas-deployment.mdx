# SaaS 部署

多账号商业版建议长期放在 `saas/multi-user` 分支；`main` 保持与原作者 fork 同步。上游更新后先同步 `main`，再把 `main` merge 到 `saas/multi-user`。

## 服务组成

- `web`：Next.js 前端，未登录时仍支持本地模式，登录后 AI 请求走 `/api/server/ai/*`。
- `server`：Go + Gin + GORM 后端，负责账号、session、额度、后台、媒体、生成任务、产品 Agent 和模型网关代理。
- `postgres`：使用 1Panel 已有 PostgreSQL，保存账号、云端数据、额度、流水和支付预留表。
- Cloudflare R2：生产环境建议保存图片、视频和音频媒体文件。
- NewAPI：应用唯一模型入口；OpenRouter 和各厂商 BYOK 渠道只在 NewAPI 后台配置。

## Docker Compose

根目录 `docker-compose.yml` 默认只启动 `web` 和 `server`，数据库使用 1Panel 已有 PostgreSQL。`docker-compose.local.yml` 才会额外启动本地测试用 PostgreSQL。

```bash
docker compose -f docker-compose.local.yml up -d --build
```

VPS / 1Panel 可以直接使用根目录 `docker-compose.yml`，并在环境变量里配置：

```env
DATABASE_URL=postgres://ic_user:你的密码@1Panel-postgresql-NamW:5432/infinite_canvas?sslmode=disable
MODEL_GATEWAY_PROVIDER=newapi
MODEL_GATEWAY_BASE_URL=https://你的-newapi-域名/v1
MODEL_GATEWAY_INTERNAL_URL=http://newapi:3000/v1
MODEL_GATEWAY_TOKEN=你的平台 token
MODEL_GATEWAY_TIMEOUT_SECONDS=600
STORAGE_PROVIDER=r2
R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
R2_ACCESS_KEY_ID=...
R2_SECRET_ACCESS_KEY=...
R2_BUCKET=...
WORKER_ENABLED=true
WORKER_CONCURRENCY=1
WORKER_POLL_SECONDS=3
DEFAULT_LOCALE=zh-CN
```

建议在 1Panel PostgreSQL 里单独创建 `infinite_canvas` 数据库和独立用户，不要复用 NewAPI 的数据库。截图里的 `1Panel-postgresql-NamW:5432` 是容器连接地址，只有当前应用容器和 PostgreSQL 容器在同一个 Docker 网络时才能使用；如果网络不通，再改用 1Panel 显示的外部连接地址或把应用加入 PostgreSQL 所在网络。

如果 NewAPI 和本应用在同一台 VPS 或同一个 Docker 网络，优先填写 `MODEL_GATEWAY_INTERNAL_URL`，让 Go 后端走内网访问 NewAPI。NewAPI 对外通过 OpenResty、Cloudflare 小黄云和你的域名暴露，是给浏览器或管理访问使用；应用后端调用模型不依赖这个公网域名。`MODEL_GATEWAY_BASE_URL` 可以保留外部域名作为展示或 fallback，实际代理请求会优先使用 internal URL。

## NewAPI 的 OpenRouter 视频渠道

NewAPI 的 OpenRouter 类型渠道可继续承载文本和图片，但当前不能处理 `/v1/videos` 异步任务。视频模型需要单独创建一个渠道：

- 类型选择 `OpenAI`，API 地址填写 `https://openrouter.ai/api`，不要在末尾添加 `/v1`。
- 密钥填写同一个 OpenRouter API Key，模型只添加 `google/veo-3.1`、`google/veo-3.1-fast`、`google/veo-3.1-lite` 等实际启用的视频模型。
- 从原 OpenRouter 类型渠道移除这些视频模型，避免 NewAPI 把视频请求再次路由到不支持任务接口的渠道。
- 图片和文本模型仍留在原 OpenRouter 类型渠道，应用侧继续只使用同一个 NewAPI 平台 Token。

NewAPI 当前不会把渠道“参数覆盖”可靠应用到 `/v1/videos` 任务请求，因此应用会在 `google/veo-*` 视频请求体中直接添加 `provider.only = ["google-vertex"]`，确保 OpenRouter 使用同一 Workspace 下配置的 Vertex BYOK。

如果要使用 `1Panel-postgresql-NamW` 这种容器连接地址，先确认 PostgreSQL 所在网络：

```bash
docker network ls
```

1Panel 常见网络名是 `1panel-network`，可以在 `.env` 里设置：

```env
ONEPANEL_NETWORK=1panel-network
```

启动时多带一个 1Panel 网络覆盖文件：

```bash
docker compose --env-file .env -f docker-compose.yml -f docker-compose.1panel.yml up -d --build
```

如果直接使用 1Panel 的外部连接地址，例如 `161.33.3.221:5432`，则不需要加入同一个 Docker 网络，但要确保防火墙和 PostgreSQL 访问策略允许连接。

如果暂时不用 R2，可以保留 `STORAGE_PROVIDER=local`，媒体会写入容器挂载的 `./data/media`。

Compose 会把前端容器端口映射到宿主机 `3005`，后端容器通过 Docker 内网地址 `http://server:8080` 提供给前端 rewrite 使用。后端宿主机 `127.0.0.1:8085` 只用于本机调试或排障，不需要作为公网入口。

正式 HTTPS 域名下建议设置 `SESSION_COOKIE_SECURE=true`；本地或内网 HTTP 测试时保持 `false`。

## OpenResty

OpenResty 默认只需要把网站转发到前端：

```nginx
location / {
    proxy_pass http://127.0.0.1:3005;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

前端镜像内置了 `SERVER_API_URL=http://server:8080` 的 rewrite，浏览器访问 `/api/server/*` 时会先到 Next.js，再由 Next.js 在 Docker 内网转发给 Go 后端。只有当你不想经过 Next.js rewrite、希望 OpenResty 直接分流 API 时，才需要额外配置 `/api/server/` 到 `127.0.0.1:8085`。

## 当前边界

当前版本已经具备账号接口、额度事务、后台手动开通、模型网关代理、R2/local 媒体上传、云端画布项目、云端素材库、参考图编排、生成任务队列、后台生成审计和产品内 Creative Agent。登录后画布项目和 CreativeAsset 素材主路径走云端 API；未登录模式仍是浏览器本地数据。

生成记录的旧 localforage 页面入口仍在逐步迁移；Docker、R2、NewAPI 和 worker 组合需要在实际 1Panel 环境按你的域名、网络和桶权限做人工验证后再视为生产可用。
